# 常见问题

## AnyTLS Panel 会自动安装代理节点吗？

不会。它负责导入、整理、检测和分享已有节点，也可以记录流量。代理服务端本身需要单独部署和维护。

## 为什么只正式支持 Ubuntu 24.04？

部署流程不仅安装 Python 应用，还会配置 systemd、Caddy、权限、健康检查和回滚。项目在 Ubuntu 24.04 上运行完整集成测试；其他系统可能可用，但目前没有同等级保证。

## 域名已经解析，为什么 HTTPS 仍然失败？

依次检查：

1. A 和 AAAA 记录是否都指向当前服务器；
2. 云安全组和主机防火墙是否放行 TCP 80、443；
3. 80/443 是否被 Nginx、Apache 或其他服务占用；
4. 服务器是否能访问公开 ACME 服务；
5. `journalctl -u caddy -n 100 --no-pager` 中的具体错误。

错误的 AAAA 记录很常见：即使 A 记录正确，证书验证仍可能访问错误的 IPv6 地址。

## 为什么 HTTP 或内网订阅被拒绝？

这是默认安全策略，用于降低明文传输和 SSRF 风险。优先让订阅源支持 HTTPS。只有在隔离网络且完全信任输入时，才参考[配置参考](CONFIGURATION.md#网络边界例外)开启对应例外。

## 同步失败会删除原有节点吗？

不会。请求失败、解析为空或超过安全上限时，面板保留上一次成功同步的节点。只有得到有效非空结果后才替换。

## 为什么节点检测显示离线，但客户端还能使用？

面板执行的是受限 TCP/TLS 连通性探测，不是完整代理协议握手。防火墙、SNI、临时网络抖动或服务端策略都可能造成差异。先重复检测，再结合节点服务日志判断。

## 为什么内网节点不能检测？

默认禁止探测私网地址，避免面板被当成访问内网服务的跳板。可信隔离网络可启用 `ANYTLS_ALLOW_PRIVATE_NODE_PROBES=1`，公网或多人使用的面板不建议开启。

## 忘记管理员密码怎么办？

项目目前没有通过网页找回密码的功能。不要删除数据库或直接改哈希。请先备份数据库，再在私密支持渠道说明部署版本和环境，由维护者提供适用于该版本的恢复步骤。

## 分享链接泄露了怎么办？

进入对应用户服务详情重新生成订阅链接。旧 URL 会立即失效。还应检查访问日志、确认订阅使用者，并在必要时轮换上游节点凭据。

## 账号到期日和每月流量重置日是什么关系？

账号到期日仍是真实到期日，不会被改成某个月的重置日期。系统只使用它的“日”推导每月重置日：例如到期日 `2027-04-24` 表示账号在 2027 年 4 月 24 日到期，同时每月 24 日开始新的流量周期。对于 29、30、31 日，较短月份按最后一天重置。

这些日期统一按中国标准时间（`Asia/Shanghai`）的自然日计算，不受服务器采用 UTC 时区影响。

## 用户换专线后需要重新发订阅链接吗？

不需要。进入用户服务详情修改“专线账号”，该用户原有链接会继续指向新专线。只有主动点击“重新生成链接”时，旧链接才会失效。

## 首页「需要处理」包含哪些提醒？

包含用户续费、账号到期、配额使用率达到 80% 的流量告警，以及离线或未检测节点。到期提醒包含未来 30 天及已过期项目，用户服务需已开始且未暂停或停用，上游账号到期提醒仅统计活跃账号。数字按待办事项计数，同一账号同时出现到期和流量问题时计为两项。分组可折叠，列表内可滚动查看全部待办。标记已提醒只更新联系时间，续费待办会保留到续期后超出提醒范围、暂停或停用。

## 面板会自动给用户发送续费消息吗？

当前版本在首页「需要处理」的「用户续费」分组中列出未来 30 天及已过期的待办，支持复制提醒话术并记录“已提醒”时间，但不会在没有明确收件人和渠道的情况下自动发送外部消息。这样可以避免误发和泄露用户信息；需要短信、邮件或企业微信通知时，应先确定通知渠道和凭据管理方式。

## 为什么流量统计和服务商后台不同？

订阅响应中的统计、节点侧 iptables 计数和服务商计费口径可能不同。`traffic_collector.sh` 只统计 IPv4 指定端口的进出流量，而且首次运行只建立基线。共享端口、IPv6、协议开销和计费倍率都会造成差异。

## 可以把主 Token 发到每个节点吗？

不可以。主 Token 能写入全部账号。应在面板服务器用 `traffic_token.py <账号 ID>` 生成账号级 Token，每个节点只保存对应账号的 Token。

## 更新会丢失数据库吗？

标准部署脚本会保留数据库，在停服前用安全副本验证迁移，并在切换失败时自动回滚。即便如此，生产更新前仍必须建立经过验证的异机加密备份。

## 如何回滚？

```bash
/opt/anytls-panel/deploy.sh --list-backups
/opt/anytls-panel/deploy.sh --rollback latest
```

回滚后检查 `/readyz`、服务日志、管理员登录、订阅输出和账号累计流量。完整流程见[运维手册](OPERATIONS.md#更新)。

## Docker 或 Kubernetes 可以用吗？

目前没有正式支持。部署逻辑依赖 systemd、Caddy 和宿主机权限模型。自行容器化需要重新设计证书、持久化、健康检查、备份和低权限边界。

## 如何获得帮助？

先阅读[支持说明](../SUPPORT.md)，再使用对应 Issue 模板提交可复现信息。请删除域名、IP、密码、Token、订阅链接和数据库内容。安全漏洞必须按[安全策略](../SECURITY.md)私下报告。
